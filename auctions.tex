\section{Auctions on \podtm through the \bidsettm protocol}\label{sec:auctions}
In this section we show how an arbitrary auction protocol can be run on top of \podtm.
To this purpose we first define \bidsettm, a primitive for collecting a set of bids, which guarantees accountable censorship resistance and consistency among honest readers.
We then show a \bidsettm construction that uses \podtm, which an auctioneer can use to run the auction protocol.

\begin{definition}[The \bidsettm protocol]\label{def:auction-framework}
    A \emph{bid-set protocol} defines a parameter \tzero, called the \emph{starting time}.
    Two types of parties interact with it, the \emph{bidders} and the \emph{consumers}, in the following way.
    \begin{itemize}
        \item function $\opSubmitBid{\bid}$: It is called by a bidder at round \tzero to submit a bid \bid.
        \item event $\opResult{\bag, \bidcert}$: It is an event generated by a consumer. It contains a \emph{bid-set} \bag, which is a set of bids, and auxiliary information \bidcert.
    \end{itemize}
    It satisfies the following properties.
    \begin{enumerate}[leftmargin=*, align=left]
        \item Liveness:
        \begin{description}
            \item[Termination within \parAuctionTerm:]
            An honest consumer generates $\opResult{\bag, \bidcert}$ by round $\tzero + \parAuctionTerm$.
            % Liveness: In a synchronous network, the auction by an honest auctioneer concludes by $t_0 + 2\Delta + 2\delta$.
            % \oa{Notice that in asynchrony, an honest auctioneer may be blamed for liveness failure.}
        \end{description}
        \item Safety:
        
        \begin{description}
            \item [Censorship resistance:]
            If an honest bidder calls \opSubmitBid{\bid}, then $\bid \in \bag$.
            %  or a subset of the parties that run the \bidsettm protocol is accountable.
            % \hue{Bid inclusion: In a synchronous network, all honest bids are included}
            % Moreover, \emph{fair punishment} holds: an honest auctioneer cannot be held accountable for censoring bids, even in asynchronous networks.
            % \oa{Notice that, even in asynchrony, an honest auctioneer cannot be blamed, in the construction we present.}
            
            \item[Consistency:]
            If two honest consumers generate events \opResult{$\bag_1, \cdot$} and \opResult{$\bag_2, \cdot$}, then $\bag_1 = \bag_2$.
            % \hue{Single-result: If there are multiple conflicting auction results, the auctioneer can be held accountable}
            % \oa{Only in synchrony.}

        \end{description}

    \end{enumerate}
\end{definition}

As with previous protocols, we require that \bidsettm satisfies \emph{accountable safety}. This requires that, if a safety property is violated, then an \identify{} function returns a subset of the parties that run the \bidsettm protocol and are malicious, and that honest parties are never returned by \identify{}.

\subsection{Construction}
We now present \bidsettm-core, a \bidsettm construction that uses \podtm-core to write and read the bids.

\begin{remark}[Implicit sub-session identifiers]
    We assume that each instance of the \bidsettm-core protocol is identified by a unique sub-session identifier (ssid). All messages between parties are concatenated with the ssid. Moreover, the ssid is implicitly included in all messages signed by the replicas in the underlying \podtm instance.
    \end{remark}

\begin{construction}[\bidsettm-core]\label{const:bidset}
    At time \tzero, the parties start running the code shown in Algorithms~\ref{alg:bid-set-bidder}--\ref{alg:bid-set-consumer}.
    % A bidder runs \opSubmitBid{} (\Cref{alg:bid-set-bidder}), the auctioneer runs \opRunAuction{} (\Cref{alg:bid-set-auctioneer}), and a consumer runs \opReadResult{} (\Cref{alg:bid-set-consumer}), in order to output the $\opResult{\bag, \bidcert}$ event.
    The construction uses an integer $\Delta$ (looking ahead, we will prove security in synchrony, i.e., the actual network delay $\delta$ does not exceed $\Delta$).
    It also employees a pre-appointed \emph{auctioneer}, which is a party responsible to read the pod and write back to it, once a specific condition is met. This can be, for example, one of the replicas running the \podtm protocol.
\end{construction}

A bidder submits a bid by writing it on \podtm-core (\Cref{alg:bid-set-bidder}) at round \tzero.
The auctioneer (\Cref{alg:bid-set-auctioneer}) waits until the pod returns a past-perfect round larger than $\tzero + \Delta$ (\cref{line:bidset-wait-pp}). The \emph{$\delta-timeliness$ property} property of \podtm-core, given that $\delta \leq \Delta$, ensures that the bids of honest parties will have a confirmation round at most $\tzero + \Delta$, and the \emph{accountable past-perfection safety} guarantees that a malicious auctioneer cannot exclude them from the bag in \cref{line:bidset-create-bag}. The auctioneer concludes by signing the bid-set \bag and \bidcert (which can be used as evidence, in case of a safety violation) and writing a \msgbidresult{(\bag, \bidcert, \sigma)} transaction on \podInst.
As an intuition on how \bidsettm-core achieves its properties, observe that \cref{line:bidset-wait-pp} of \Cref{alg:bid-set-auctioneer} becomes true in the view of auctioneer by round $\tzero + \Delta + \delta$ (from the \emph{past-perfection within $\parPerf=\delta$} property of \podtm-core),
hence \Cref{alg:bid-set-auctioneer} for an honest auctioneer terminates by that round.
Observe also that the transaction \msgbidresult{(\bag, \bidcert, \sigma)} becomes confirmed in the view of all honest clients by round $\tzero + \Delta + 3\delta$ (from the \emph{confirmation within $\parConf=2\delta$} property), and it will have a confirmed round $\rconf \leq \tzero + \Delta + 2\delta$ (from the \emph{$\delta$-timeliness} property).

The code for a consumer is shown in \Cref{alg:bid-set-consumer}. The consumer waits until one of the following two conditions is met. 
First, a \emph{confirmed} transaction \msgbidresult{(\bag, \bidcert, \sigma)} appears in \txSet , for which $\rconf \leq \tzero + 3 \Delta$ (\cref{line:bidset-find-confirmed-tx}), in which case it outputs the bid-set \bag it the \opResult{} event.
Second, a round higher than $\tzero + 3 \Delta$ becomes past-perfect in \podtm (\cref{line:bidset-read-result-pp}), in which case it outputs an empty bid-set.

Observe that, from the \emph{past-perfection within $\parPerf=\delta$} property of \podtm-core, the condition in \cref{line:bidset-read-result-pp} will become true at latest at round $\tzero + 3 \Delta + \delta$, hence \bidsettm-core achieves \emph{termination within $\parAuctionTerm=3\Delta + \delta$}.
If the network is synchronous and the auctioneer honest, the condition in \cref{line:bidset-find-confirmed-tx} becomes true at round at most $\tzero + \Delta + 3\delta$ for an honest consumer, hence it outputs \bag as the bid-set, hence \bidsettm-core satisfies the \emph{consistency} property.

\begin{theorem}[Bidset security]\label{thm:bidset-construction-secure}
Assuming a synchronous network (that is, $\delta \leq \Delta$),
the \bidsettm-core protocol (Construction~\ref{const:bidset}), instantiated with a secure \podtm protocol that satisfies the \emph{past-perfection within $\parPerf = \delta$} and \emph{$\delta$-timeliness} properties, is a secure \bidsettm protocol satisfying \emph{termination within $\parAuctionTerm = 3\Delta + \delta$}.
It satisfies accountable safety using the \identifyAuctioneer{} function of \Cref{alg:identify-bidset}, which identifies a malicious auctioneer.
\end{theorem}
\begin{proof}
In Lemmas \ref{lem:bidset-termination}--\ref{lem:bidset-accountability}. The function for identifying a malicious auctioneer is shown in \Cref{alg:identify-bidset}.
\end{proof}

\begin{remark}
    \wip{reread}
    The protocol uses one step where we wait for $\Delta$.
    This is due to the fact that the set of bidders is not known, and we give them sufficient time.
    If this set is known, the protocol can be made fully responsive in the optimistic case where all bidders and the auctioneer are honest.
\end{remark}
