\section{Auctions on \podtm through the \bidsettm protocol}\label{sec:auctions}
In this section, we construct single-shot distributed auctions based on top of \podtm by means of \bidsettm, a primitive for collecting a set of bids, which guarantees accountable censorship resistance and consistency among honest parties. We first define \bidsettm below and then construct it using an underlying \podtm.
%We then show a \bidsettm construction that uses \podtm, which an auctioneer can use to run the auction protocol.

\begin{definition}\bidsettm protocol]\label{def:auction-framework}
    A \bidsettm \emph{protocol} is parameterized by a \emph{starting time} \tzero and implements the following interfaces for \emph{bidder} and  \emph{consumer} parties:
    \begin{itemize}
        \item function $\opSubmitBid{\bid}$: It is called by a bidder at round \tzero to submit a bid \bid.
        \item event $\opResult{\bag, \bidcert}$: It is an event generated by a consumer. It contains a \emph{bid-set} \bag, which is a set of bids, and auxiliary information \bidcert.
    \end{itemize}
    A \bidsettm protocol satisfies the following liveness and safety properties:
        \begin{description}[leftmargin=1mm]
        	\item[(Liveness) Termination within \parAuctionTerm:]
        	An honest consumer generates $\opResult{\bag, \bidcert}$ by round $\tzero + \parAuctionTerm$.
        	
            \item [(Safety) Censorship resistance:]
            If an honest bidder calls \opSubmitBid{\bid}, then $\bid \in \bag$.
            %  or a subset of the parties that run the \bidsettm protocol is accountable.
            % \hue{Bid inclusion: In a synchronous network, all honest bids are included}
            % Moreover, \emph{fair punishment} holds: an honest auctioneer cannot be held accountable for censoring bids, even in asynchronous networks.
            % \oa{Notice that, even in asynchrony, an honest auctioneer cannot be blamed, in the construction we present.}
            
            \item[(Safety) Consistency:]
            If two honest consumers generate events \opResult{$\bag_1, \cdot$} and \opResult{$\bag_2, \cdot$}, then $\bag_1 = \bag_2$.
            % \hue{Single-result: If there are multiple conflicting auction results, the auctioneer can be held accountable}
            % \oa{Only in synchrony.}

        \end{description}

\end{definition}

%As with previous protocols, we require that \bidsettm satisfies \emph{accountable safety}. This property means that, if a safety property is violated, then an \identify{} function returns a subset of the parties that run the \bidsettm protocol and are malicious, and that honest parties are never returned by \identify{}.

\subsection{Construction}
We present \bidsettm-core, a \bidsettm construction that uses a \podtm to register bids.


\begin{construction}[\bidsettm-core]\label{const:bidset}
	Protocol \bidsettm-core is parameterized by an integer $\Delta$ (looking ahead, we will prove security in synchrony, \textit{i.e.}, assuming the network delay $\delta$ is smaller than $\Delta$) and assumes digital signatures and a \podtm with $\delta$-timeliness, $\parPerf=\delta$ and $\parConf=2\delta$. At time \tzero, all parties start executing Algorithms~\ref{alg:bid-set-bidder}--\ref{alg:bid-set-consumer}.
	% A bidder runs \opSubmitBid{} (\Cref{alg:bid-set-bidder}), the auctioneer runs \opRunAuction{} (\Cref{alg:bid-set-auctioneer}), and a consumer runs \opReadResult{} (\Cref{alg:bid-set-consumer}), in order to output the $\opResult{\bag, \bidcert}$ event.
	A pre-appointed \emph{auctioneer} is responsible to reading the \podtm and writing back to it when a specific condition is met. For example, when instantiating \bidsettm-core on top of \podtm-core, a replica can act as auctioneer.
\end{construction}


A bidder submits a bid by writing it on the \podtm (\Cref{alg:bid-set-bidder}) at round \tzero.
The auctioneer (\Cref{alg:bid-set-auctioneer}) waits until the \podtm returns a past-perfect round larger than $\tzero + \Delta$ (\cref{line:bidset-wait-pp}). The \emph{$\delta$-timeliness property} of the \podtm, given that $\delta \leq \Delta$, ensures that the bids of honest parties will have a confirmation round at most $\tzero + \Delta$, and the \emph{accountable past-perfection safety} guarantees that a malicious auctioneer cannot exclude them from the bid-set $\bag$ in \cref{line:bidset-create-bag}. The auctioneer concludes by signing \bag and \bidcert (which can be used as evidence, in case of a safety violation) and writing  \msgbidresult{(\bag, \bidcert, \sigma)} on \podInst.
As an intuition on how \bidsettm-core achieves its properties, observe that \cref{line:bidset-wait-pp} of \Cref{alg:bid-set-auctioneer} becomes true in the view of auctioneer by round $\tzero + \Delta + \delta$ (from the \emph{past-perfection within $\parPerf=\delta$} property of \podtm-core),
hence \Cref{alg:bid-set-auctioneer} for an honest auctioneer terminates by that round.
Observe also that the transaction \msgbidresult{(\bag, \bidcert, \sigma)} becomes confirmed in the view of all honest clients by round $\tzero + \Delta + 3\delta$ (from the \emph{confirmation within $\parConf=2\delta$} property), and it will have a confirmed round $\rconf \leq \tzero + \Delta + 2\delta$ (from the \emph{$\delta$-timeliness} property).

The code for a consumer is shown in \Cref{alg:bid-set-consumer}. The consumer waits until one of the following two conditions is met. 
First, a \emph{confirmed} transaction \msgbidresult{(\bag, \bidcert, \sigma)} appears in \txSet , for which $\rconf \leq \tzero + 3 \Delta$ (\cref{line:bidset-find-confirmed-tx}), in which case it outputs the bid-set \bag it the \opResult{} event.
Second, a round higher than $\tzero + 3 \Delta$ becomes past-perfect in \podtm (\cref{line:bidset-read-result-pp}), in which case it outputs $\bag=\emptyset$.

Observe that, from the \emph{past-perfection within $\parPerf=\delta$} property of \podtm, the condition in \cref{line:bidset-read-result-pp} will become true at latest at round $\tzero + 3 \Delta + \delta$, hence \bidsettm-core achieves \emph{termination within $\parAuctionTerm=3\Delta + \delta$}.
If the network is synchronous and the auctioneer honest, the condition in \cref{line:bidset-find-confirmed-tx} becomes true at round at most $\tzero + \Delta + 3\delta$ for an honest consumer, hence it outputs \bag as the bid-set, hence \bidsettm-core satisfies the \emph{consistency} property.


\begin{remark}[Implicit sub-session identifiers]
	We assume that each instance of the \bidsettm-core protocol is identified by a unique sub-session identifier (ssid). All messages written to the underlying \podtm are concatenated with the ssid.
\end{remark}


\begin{theorem}[Bidset security]\label{thm:bidset-construction-secure}
Assuming a synchronous network where $\delta \leq \Delta$,
protocol \bidsettm-core (Construction~\ref{const:bidset}) instantiated with a digital signature and a  secure \podtm protocol that satisfies the \emph{past-perfection within $\parPerf = \delta$}, \emph{confirmation within $\parConf=2\delta$} and \emph{$\delta$-timeliness} properties, is a secure \bidsettm protocol satisfying \emph{termination within $\parAuctionTerm = 3\Delta + \delta$}.
It satisfies accountable safety with an \identifyAuctioneer{} function that identifies a malicious auctioneer.
\end{theorem}
\begin{proof} The proof and \identifyAuctioneer{} are shown in Appendix~\ref{app:bidsetsec}.
\end{proof}

\begin{remark}
    Observe that \bidsettm-core terminates within $\parAuctionTerm = 3\Delta + \delta$ in the worst case, but, if the auctioneer is honest, then it terminates within $\parAuctionTerm = \Delta + 3\delta$.
    Moreover, \bidsettm-core is not responsive because \Cref{alg:bid-set-auctioneer} waits for a fixed $\Delta$ interval.
    This step can be optimized if the set of bidders is known (i.e., by requiring them to pre-register), which allows for the protocol to be made optimistically responsive when all bidders and the auctioneer are honest.
\end{remark}

\dotparagraph{\textbf{Auctions using \bidsettm}} Building on a \bidsettm protocol, it is trivial to construct single-shot first price and second price open auctions: 1. Bidders place their open bids $\bid$ by calling \opSubmitBid{\bid}; 2. Consumers determine the winner by calling \opReadResult{} to obtain $\bag$ and outputting either the first or second highest bid. We conjecture that single-short sealed bid auction protocols such as those of~~\cite{trustee,seal,ACNS:DavGenPou22,CCS:TAFWBM23,chitra_et_al:LIPIcs.AFT.2024.19,cryptoeprint:2024/1011} can also be instantiated on top of a \bidsettm protocol. Intuitively, this holds because such protocols first agree on a set of sealed bids and then execute extra steps to determiner the winner. However, a formal analysis of sealed-bid auction protocols based on \bidsettm is left as future work.
